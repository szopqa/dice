# ADR: Remove Undo and Re-roll outright, with the pure functions and an unchanged save format
- Status: Accepted
- Date: 2026-11-15
- Spec: specs/catan-dice.md (Amendment 1)
- Supersedes: none

> The original catan-dice build predates ADRs, so this file has no earlier version. It covers only Amendment 1 (simplify controls). Task ids continue from `specs/turn-timer.adr.md` (T1–T7, R1), because both features ship on `feat/turn-timer` (PR #4).

## Context
Amendment 1 removes the Undo and Re-roll buttons. To fix a mistake, players use ◀ / ▶ and roll again. AC-6, AC-7 and AC-19 are retired, AC-24 and AC-26 drop the two buttons, and AC-30..AC-33 are new. Re-roll and Undo currently reach four places: the pure functions `rerollLast`/`undoLast` in `js/game.js` (tested as AC-6/AC-7 in `test/game.test.js`, AC-19 in `test/events.test.js`), the wiring in `js/main.js` (imports, `el.reroll`/`el.undo`, `reroll`, two click listeners, the disabled state in `renderButtons`, and the `apply` parameter of `rollWith`, which exists only for re-roll), the two buttons in `index.html` inside `.row--4`, and the `.row--4` CSS rule that squeezes four labels into 360 px. The save format (`catan-dice:game` = `serialize(game)`, `version: 1`) was never affected by Re-roll or Undo: both only produced ordinary `{ dice, sum, player }` rolls and a valid `turn`. So AC-33 needs no code, only a test that pins it. The AC ids AC-30 and AC-31 collide with `specs/mobile-sound-haptics-shake.md` (AC-30..AC-35). That spec and turn-timer already solve this with their own test files and a `describe("<spec-slug>", …)` wrapper.

## Decision
We will delete `rerollLast` and `undoLast` from `js/game.js`, together with the AC-6, AC-7 and AC-19 tests. Nothing uses them once the buttons are gone, their ACs are retired, and keeping untested-by-spec exports would leave tests that name dead ACs (CLAUDE.md requires tests to name live ACs). Deleting them also makes AC-31 enforceable: `applyRoll` becomes the only export that touches `rolls`, and it only appends. In `main.js` we remove every Re-roll/Undo reference. We also fold `rollWith(apply, viaShake)` into `roll(viaShake = false)`, which calls `applyRoll` directly and keeps the `viaShake === true` guard, so `roll()`, `roll(true)` and `() => roll()` behave as before. `renderButtons` keeps `el.roll.disabled = animating` and `el.prev/next/newGame.disabled = animating` unchanged (AC-30). The two buttons are removed from `index.html`. The ◀ / ▶ row loses its `row--4` modifier and becomes a plain `.row` (two `flex: 1` buttons, 48 px tall, via the existing `.row .btn` and `.btn` rules), and we delete the now-unused `.row--4` CSS rule. `serialize`, `deserialize`, `VERSION` and `ui/storage.js` stay as they are (AC-33).

Tests for AC-30..AC-33 go in a new file `test/catan-dice-controls.test.js`, inside `describe("catan-dice", …)`, with titles starting with the AC id (`it("AC-32: …")`). This matches `describe("turn-timer")` and `describe("mobile-sound-haptics-shake")`, so the reporter prints `catan-dice > AC-30: …` and the mobile spec's `AC-30` stays distinct. The existing top-level catan-dice tests are not re-wrapped. The UI ACs are guarded with static source checks, following the `readFileSync` pattern of `test/workflow.test.js`, and the rest is still manual QA, as the spec says.

## Alternatives considered
- Keep `rerollLast`/`undoLast` (and their tests) as unused exports, which the spec allows "if cheap" — rejected. They cost little to keep, but they leave tests titled with retired AC ids, a public API with no caller, and nothing that guards AC-31. Deleting them is fewer lines and makes "no input can remove or replace a roll" true by construction.
- Hide the buttons (`hidden` attribute or CSS) and leave the handlers in place — rejected. That leaves dead code paths, still renders disabled state for invisible controls, and a stray CSS change could bring the buttons back, which breaks AC-30.
- Put the amendment tests into `test/game.test.js` / `test/events.test.js` as top-level `test("AC-30: …")` — rejected. A bare `AC-30` title is ambiguous with the mobile spec. A dedicated file with `describe("catan-dice")` matches how the other two specs avoid the collision, and keeps the retired-test deletions separate from the new tests.

## Consequences
- Positive: about 30 fewer lines across `game.js`/`main.js`/CSS, one fewer indirection in the roll path, and a two-button turn row with bigger ◀ / ▶ targets. This makes the 360×640 fit (AC-26) easier, not harder.
- Positive: AC-33 is pinned by literal legacy JSON strings, so any future accidental format change fails a test.
- Negative / trade-offs: AC-30's "work as in AC-24/26/8/28" and the visual layout stay manual QA. The static checks only prove the buttons and their wiring are gone, not how the page looks.
- Negative / trade-offs: a mistaken roll stays in the history and counts toward streaks, drought and serial robber (AC-32). The spec intends this.
- Cost & performance: none. No new runtime work, no storage change, no migration.
- Risks: removing the HTML buttons without the `main.js` references (or the reverse) throws at load (`el.reroll` is `null`), and `npm test`/lint would not catch it, because no test imports `main.js` → both changes happen in the same task (T8), the AC-30 static test checks both files, and T8 ends with a manual page load.
- Risks: deleting `game.js` exports while `main.js` still imports them breaks the module graph in the browser only → T8 (which removes the imports) comes before T9 (which deletes the exports), and the AC-31 test asserts `main.js` no longer names them.

## Spec changes
- `specs/mobile-sound-haptics-shake.md` Out of scope: "the only possible haptic is the tick on the Roll/Re-roll tap" → "the only possible haptic is the tick on the Roll tap" — Re-roll no longer exists (catan-dice Amendment 1).
- `specs/mobile-sound-haptics-shake.md` AC-25: "when Roll or Re-roll is tapped" → "when Roll is tapped" — same reason. The haptic behaviour for Roll is unchanged.
- `specs/mobile-sound-haptics-shake.md` AC-26: "when Roll or Re-roll is tapped (or Space/Enter is pressed)" → "when Roll is tapped (or Space/Enter is pressed)" — same reason.
- `specs/mobile-sound-haptics-shake.md` AC-34: "exactly once per roll, re-roll and shake roll" → "exactly once per roll, whether it was started by a tap, a key or a shake" — same reason. The once-per-roll rule and the shake case are kept.
- Related ADR edits (not a spec): `specs/turn-timer.adr.md` Decision, "`updateGame` (Undo, ◀/▶)" → "`updateGame` (◀/▶; Undo was removed by catan-dice Amendment 1)"; state diagram edge "[reveal, Undo, prev/next, cycle press, load]" → "[reveal, prev/next, cycle press, load]". The decision itself does not change: `updateGame` still resets the timer on ◀/▶.
